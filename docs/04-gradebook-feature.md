# ฟีเจอร์: ตารางคะแนนละเอียด (Detailed Gradebook)

## ที่มา

ปลั๊กอิน MasterStudy LMS Pro มีหน้า "Gradebook" ของผู้สอนอยู่แล้ว แต่แสดงเป็น**ค่าสรุป** (จำนวน lesson/quiz/assignment ที่ผ่าน เป็น % รวม) ไม่สามารถดูคะแนนแยกตามชื่อ quiz/assignment แต่ละตัว และไม่มีช่องกรอกคะแนน midterm/final เลย จึงพัฒนาเพิ่มเป็นตารางคะแนนละเอียดแบบ spreadsheet

## สิ่งที่ทำได้

**ฝั่งผู้สอน**
- เลือกคอร์สแล้วกดปุ่ม "📋 ตารางคะแนนละเอียด" ที่หน้า Gradebook เดิม → เปิดเป็นหน้าเต็มจอ (full-screen overlay)
- ตารางแสดง 1 แถวต่อนิสิต คอลัมน์: รหัสนิสิต, ชื่อ-นามสกุล, หมู่เรียน, Quiz1...QuizN (อ่านอย่างเดียว ดึงจากผลสอบจริง, โชว์ badge ถ้าส่งช้า), Assignment1...AssignmentN (แก้ไขได้ พิมพ์แล้ว auto-save), Midterm, Final (แก้ไขได้)
- กรองดูเฉพาะหมู่เรียนได้ (dropdown) — กรองแบบ client-side ไม่ต้องยิง API ใหม่
- ตั้งคะแนนเต็มของ Midterm/Final ได้ต่อคอร์ส (ค่าเริ่มต้น 100)
- Export ตารางทั้งหมด (หรือเฉพาะหมู่เรียนที่กรองไว้) เป็นไฟล์ Excel (.xls) ได้
- หัวตารางค้างด้านบน (sticky header) เวลาเลื่อนดูรายชื่อยาวๆ

**ฝั่งผู้เรียน**
- หน้า "My Grades" มีบล็อกใหม่ให้เลือกวิชาที่ลงทะเบียนอยู่ แล้วดูคะแนนของตัวเองแบบอ่านอย่างเดียว (คอลัมน์เดียวกับฝั่งผู้สอน ไม่มีช่องแก้ไข)

## ที่เก็บข้อมูล

| ข้อมูล | เก็บที่ | หมายเหตุ |
|---|---|---|
| คะแนน quiz | `wp_stm_lms_user_quizzes.progress` (ของเดิม) | ไม่ได้สร้างที่เก็บใหม่ — อ่านอย่างเดียว |
| คะแนน assignment | `wp_stm_lms_user_assignments.grade` (ของเดิม) | แก้ไขผ่านตารางนี้ได้ ถ้านิสิตยังไม่เคยส่งงาน ระบบจะสร้างแถวคะแนนแบบ manual ให้ (status ว่าง — **ยังไม่ได้ตรวจสอบกับ enum status เต็มของ Assignments addon** ถ้าอยากให้ตรงกับสถิติ "ส่งงานแล้วกี่คน" ของปลั๊กอินเป๊ะ ต้องตรวจเพิ่ม) |
| คะแนน midterm/final | ตารางใหม่ `wp_ku_lms_gradebook_scores` (course_id, user_id, midterm_point, final_point, updated_by, updated_at) | ไม่มีที่เก็บเดิมในระบบ จึงสร้างตารางใหม่ |
| คะแนนเต็ม midterm/final | post meta `ku_midterm_max_point` / `ku_final_max_point` ของคอร์ส | ค่าเริ่มต้น 100 ถ้ายังไม่เคยตั้ง |

## REST API

ดูรายการเต็มใน [02-architecture.md](02-architecture.md#rest-api-ที่พัฒนาเอง-ku-lmsv1) หัวข้อ `/gradebook/*`

ทุก endpoint ตรวจสิทธิ์ด้วยกฎเดียวกับ Gradebook เดิมของปลั๊กอิน: ต้องเป็นเจ้าของคอร์สหรือผู้สอนร่วม และถ้าผู้สอนร่วมถูกจำกัดเฉพาะบางหมู่เรียน (`_co_instructor_sections_{user_id}`) จะเห็น/แก้ไขได้เฉพาะนิสิตในหมู่เรียนนั้นเท่านั้น ทั้งตอนดูตารางและตอนบันทึกคะแนน

## วิธีฝัง UI เข้าไปในหน้าเดิมของปลั๊กอิน (เทคนิคสำคัญ)

เนื่องจากไม่ต้องการแก้ template ของปลั๊กอิน Pro โดยตรง (จะถูกเขียนทับตอนอัปเดต) จึงใช้วิธี:

1. เกาะ `wp_footer` แบบมีเงื่อนไข `wp_script_is('masterstudy-account-gradebook', 'enqueued')` เพื่อให้โค้ดทำงานเฉพาะหน้า Gradebook เท่านั้น
2. echo HTML/CSS/JS ของปุ่มและ panel ออกมา — ตำแหน่งที่ echo จะอยู่ท้ายสุดของหน้า (ใกล้ `</body>`)
3. ใช้ jQuery ย้ายตำแหน่ง element ไปไว้ข้างๆ ช่องเลือกคอร์สของจริง (`.masterstudy-account-gradebook__course-select`) หลังหน้าโหลดเสร็จ ด้วย `.after()`

> **บทเรียนที่ได้:** รอบแรกที่ทำฟีเจอร์นี้ลืมย้ายตำแหน่ง ปุ่มเลย echo ค้างอยู่ท้ายสุดของหน้าโดยไม่มีใครเห็น ถ้าทำฟีเจอร์แทรก UI แบบนี้อีกในอนาคต **อย่าลืมขั้นตอนย้ายตำแหน่งด้วย jQuery เสมอ**

## Full-screen overlay

ใช้ `position: fixed; inset: 0; z-index: 999999;` คลุมทั้งหน้าจอ ล็อก scroll ของ `<body>` ตอนเปิด ปิดด้วยปุ่ม "✕ ปิด" หรือกด `Esc`
